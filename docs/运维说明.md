# 运维与异常演示

## 启停与端口

正式构建页面与 API 同源位于 8000；目录模拟服务 8001；计费模拟服务 8002。开发 Vite 为 5173。默认全部绑定 `127.0.0.1`，没有对校园网络开放。启停脚本记录 PID 及进程创建时间，只停止本项目启动的匹配进程，不按端口杀其他程序。

`.runtime/api.log`、`catalog.log`、`billing.log`、`worker.log` 是应用日志。脚本不会重置数据库，重启后的草稿、正式课表、成绩、账单和待发任务保留。任务发送失败时，可在教务“计费任务”查看尝试次数和重试状态。

独立 MySQL 数据目录在 `.runtime/mysql-data`，3307 仅监听本机。停止应用不会关闭 MySQL。需要关闭私有数据库时，可用 MySQL 管理工具连接该实例执行 `SHUTDOWN`；不要停止电脑原有的 3306 服务。启动脚本会在下次启动时检查并启动项目私有实例。

## 模拟外部系统异常

在项目目录执行：

```powershell
# 课程目录不可用；当前有效缓存最多继续使用 60 秒。
.\.venv\Scripts\python.exe .\scripts\manage.py mock-mode --service catalog --offline
# 目录慢响应；HTTP 总期限为 7.5 秒。
.\.venv\Scripts\python.exe .\scripts\manage.py mock-mode --service catalog --delay 12
# 恢复目录。
.\.venv\Scripts\python.exe .\scripts\manage.py mock-mode --service catalog
# 计费宕机及恢复。恢复后任务按退避计划自动补发，可手动“立即重试”。
.\.venv\Scripts\python.exe .\scripts\manage.py mock-mode --service billing --offline
.\.venv\Scripts\python.exe .\scripts\manage.py mock-mode --service billing
```

目录故障期间已经落库的课表、成绩和账单仍可查询。需要重新读取目录的操作在无有效缓存时返回明确错误。工作进程重启不会丢任务；认领后未完成的任务在 30 秒租约过期后重新发送，接收方去重。

QA 模拟故障文件在 `.runtime/qa/`，与演示环境故障设置分开。自动化故障验收只修改 QA 设置。

## 数据库账户与配置

初始化器需要能 `CREATE DATABASE`、`CREATE USER`、`GRANT` 的本机 MySQL 管理员。业务进程随后使用 `cr_app_*` 最小权限账户，仅访问项目业务表；`cr_catalog_*` 仅 SELECT 外部目录模拟表；`cr_billing_*` 仅访问模拟计费接收表；`cr_test_*` 只管理 `_test` 数据库。

`.env` 包含业务连接、Fernet 密钥及模拟服务集成密钥；管理员密码不会写入 `.env`。只有选择私有实例时，脚本为自己创建的实例保存随机管理密码到 `.runtime/mysql-admin.json`。敏感配置和演示密码限制为当前 Windows 用户及 SYSTEM 可读，不提交版本控制。

生产环境需要 HTTPS 反向代理、`APP_ENV=production`、`COOKIE_SECURE=true` 和准确的 `ALLOWED_ORIGINS`。跨主机服务应使用 TLS、数据库网络访问控制、集中日志与监控，并评估真实容量；默认本机演示配置不直接开放到公网。

项目私有数据库通过 `DATABASE_SSL_CA` 固定信任初始化时生成的 MySQL CA，连接复用 SSLContext；本机回环地址使用该 CA 验证，跨主机地址还会校验主机名。真实数据库应提供自己的可信 CA。启动脚本默认每个 API 服务 2 个工作进程，每个进程固定 8 个数据库连接，不临时扩容连接池，减少 Windows 证书加载及连接建立开销。

## 外部目录适配

`HttpCatalogAdapter` 使用 `CATALOG_URL` 和集成头读取目录；`SQLCatalogAdapter` 在 `CATALOG_MODE=sql` 时使用 `CATALOG_DATABASE_URL`，执行参数化只读查询 `SELECT document FROM legacy_catalog WHERE id=:id`。模拟目录的独立数据库账户无写权限。

适配器文档结构为 `revision/courses/offerings`。课程含 `id/code/name/department/description/credits`，教学班含 `id/code/semester_id/course_id/fee`。真实目录接入要在新学期开放前导入与本地用户、学期相匹配的课程、先修关系、教学班和课时结构；本地教学班 ID 需要稳定映射。开放期的展示字段可刷新，结构变化需要显式的数据迁移。真实 Ingres/DEC VAX 驱动和连接信息未伪造，属于实际环境联调内容。

## 备份与恢复

备份时保留数据库、`.env` 的加密密钥和配置，以及应用锁文件版本；**只有数据库备份而没有原加密密钥，就不能解密历史身份号码**。把备份放在受访问控制、与源数据不同的位置。备份示例在 PowerShell 中用真实项目数据库名替换占位符，`-p` 会交互读取密码：

```powershell
# 使用有备份权限的管理员；3306 对应已有服务，私有演示实例改为 3307。
# --result-file 由 mysqldump 直接写文件，避免 PowerShell 改变 SQL 文件编码。
& 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe' --host=127.0.0.1 --port=3306 --user=root -p --single-transaction --no-tablespaces --set-gtid-purged=OFF --result-file=D:\backups\course-registration.sql course_registration
```

恢复先停止应用，在数据库管理工具中**创建新的空项目数据库**，导入备份 SQL，再为项目账户授予该库对应表的权限，更新 `.env` 连接并保留原 `ENCRYPTION_KEY`。恢复前核对目标库名，避免覆盖其他课程项目。恢复后检查：Alembic 版本、用户和教学班数量、成绩与账单样本、`/api/v1/health`、三角色登录和待发任务处理。若恢复备份包含已发送前后的不确定状态，接收方仍按事件和账单唯一键去重。

建议每日全量备份、重要演示或结束选课前额外备份；恢复流程应定期在新的空库演练。备份频率和保留期限由实际数据的重要程度决定。

## 监控与升级

健康检查返回数据库连通性；另需监控计费 PENDING/PROCESSING 积压、最后成功发送时间、磁盘空间、MySQL 连接数及错误率。7×24 可用率要靠持续监控记录计算，短时压测不能证明。

先在测试环境运行 `scripts/test.ps1`、`scripts/audit.ps1` 和浏览器流程，再更新依赖与锁文件。数据库升级使用 Alembic，由维护者使用临时 DDL 权限运行；业务账户无建表权限。每次升级前备份，不对有数据的实例执行 `alembic downgrade base`。

```powershell
# 已有服务：交互输入维护账户，升级 .env 指定的项目数据库。
.\.venv\Scripts\python.exe .\scripts\migrate.py
# 当前项目私有实例：核对端口后使用初始化器保存的私有管理凭据。
.\.venv\Scripts\python.exe .\scripts\migrate.py --isolated
```

迁移 `0002` 将首次提交时间保留至微秒，保证同一秒内的先后提交仍按实际提交时间处理备选；时间完全相同才按学生编号排序。

本机 Python 3.12 的安装目录中存在一个与 pytest 同名的 `py.py`，因此使用 `scripts/run_tests.py` 显式加载虚拟环境里的 pytest 兼容模块；没有修改全局 Python。临时文件与 npm 缓存放在项目所在磁盘的 `.runtime`，避免依赖系统临时盘空间。
