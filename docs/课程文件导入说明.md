# 课程文件一键导入

## 使用步骤

1. 使用教务管理员账号登录，进入左侧 **课程文件导入**。
2. 选择尚未结束的开放学期，点击 **下载当前学期示例**。项目也附带 [课程目录示例.json](../数据导入/课程目录示例.json)，对应演示学期 `CURRENT`。
3. 在文本编辑器中修改示例，保存为 UTF-8 编码的 `.json` 文件。
4. 点击 **选择 JSON 文件**，然后点击 **一键导入**。也可先点击 **仅校验预览**，查看新增和跳过的记录。
5. 导入成功后，学生和教授刷新课程目录即可看到新教学班。教务先维护教授的任课资格，再由教授选择任课。新教学班人数为 0、容量为 10，尚无授课教授。

文件一次描述课程、教学班、先修关系和上课时间，无需逐门手工录入。初次导入成功后，系统将文件视为外部课程目录来源，不再依赖原 HTTP/只读 SQL 模拟目录查询。原文件对象与合并目录持久保存于数据库，容器重启或本机系统重启后依然有效；后续文件继续新增目录内容。

## 文件结构

顶层只有 `format_version`、`semester_code`、`courses`、`offerings` 四个字段。不接受额外字段。`format_version` 固定为整数 `1`，`semester_code` 必须与目标学期一致。

| 位置 | 字段 | 填写规则 |
|---|---|---|
| courses[] | code | 课程代码，1～40位；英文字母、数字、点、下划线、短横线，首位字母或数字；不区分大小写 |
| courses[] | name | 课程名称，必填，最多100字符 |
| courses[] | department | 院系名称，必填，最多80字符 |
| courses[] | credits | 大于0且不超过999.9，最多1位小数，可写为 `"3.0"` |
| courses[] | description | 可省略，最多10000字符，默认空文本 |
| courses[] | prerequisites | 先修课程代码列表，可省略，默认空列表；最多32项 |
| offerings[] | code | 教学班代码，1～50位；字符规则同课程代码；在所有学期中唯一 |
| offerings[] | course_code | 课程代码，可引用本文件课程或已存在课程 |
| offerings[] | fee | 0～99999999.99，最多2位小数，例如 `"600.00"` |
| offerings[] | capacity | 固定为整数10，可省略 |
| offerings[] | meetings | 1～16段上课时间 |
| meetings[] | weekday | 整数1～7，对应周一至周日 |
| meetings[] | start / end | 24小时 `HH:MM`，例如 `14:00` / `15:40`；结束必须晚于开始，不支持跨日 |
| meetings[] | week_start / week_end | 正整数，结束周不早于开始周，且不超过所选学期的周数，最多53 |
| meetings[] | room | 教室，必填，最多60字符 |

同一文件最多500门课程、500个教学班，UTF-8文件大小不超过256KB。`courses` 可以为空列表，用于为已有课程新增教学班；`offerings` 至少一条。不要自行填写数据库编号、已选人数、教授编号、学生数据或成绩。

先修课程必须已经存在或在当前文件中声明。不能自引用、重复或形成循环依赖。同一教学班的时间段不能在相同星期、相交周次中发生重叠；学生选课和教授任课仍按原业务规则检查各教学班间的时间冲突。

## 重复、冲突与事务

- 采用新增导入。相同代码、相同内容的记录直接跳过，不增加座位、不重复生成课程和教学班。
- 已有代码但名称、学分、先修关系、费用或课时等内容不同，则列出具体位置并整批拒绝。需要新增不同课程或教学班时使用新的代码。
- 不会因文件省略某条记录而删除它，也不会修改原有选课、任课、成绩或账单。
- 任意校验错误或数据库写入失败，课程、先修关系、教学班、课时和文件目录快照整体回滚。
- 学期已结束、其他用户正在提交选课/任课或结束选课时，导入被拒绝并提示重试。
- 校验预览不保存数据，正式导入会重新核验。多页面同时导入同一文件时不会创建重复数据。
- 仅管理员可访问导入、预览、来源状态与示例接口，修改请求仍需合法登录、来源和 CSRF 校验。

页面错误明细显示“课程/教学班第几条—字段—原因与修改方法”；JSON语法错误另外指出行号和列号。错误会保留在页面，不会被自动刷新清除。最多展示100处错误，修改后可继续校验剩余内容。

## 接口和数据保存

| 接口 | 用途 |
|---|---|
| `GET /api/v1/registrar/catalog/source` | 查看当前目录来源和最近文件 |
| `GET /api/v1/registrar/catalog/template?semester_id=2` | 生成对应学期的示例 |
| `POST /api/v1/registrar/catalog/preview` | 只校验并返回预览 |
| `POST /api/v1/registrar/catalog/import` | 校验并原子导入 |

两个 POST 接收 JSON：`semester_id`、`filename`、`content`。`content` 是上传文件的原始文本，服务端自行解析，不执行文件内容，不根据文件名访问服务器路径。接口外层请求限制2MB用于容纳JSON转义，实际文件仍限制256KB；其他接口继续限制64KB。

`file_catalog` 保存最近文件名、SHA-256、原始JSON对象、包含旧数据的合并目录、导入人、时间和随机版本；操作审计另记录每次实际新增的结果。来源文件对象不是完整数据库备份，备份仍需使用项目数据库备份流程。

Docker 环境重新运行一键部署脚本即可，由初始化器执行迁移和新表授权。新安装通过原初始化流程自动创建。
